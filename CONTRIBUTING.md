# Como contribuir

Todos os integrantes devem realizar contribuições reais, identificadas com suas próprias contas e dados de autoria. A organização inicial do repositório não substitui a participação de cada integrante.

## Fluxo sugerido

1. Combinar a tarefa com a dupla e vinculá-la ao requisito correspondente.
2. Atualizar a cópia local da branch principal.
3. Criar uma branch descritiva, como `feat/crud-livros` ou `docs/regras-troca`.
4. Fazer alterações pequenas e coerentes.
5. Executar os testes aplicáveis quando houver código.
6. Criar commits descrevendo o trabalho efetivamente realizado.
7. Abrir um pull request explicando a alteração e a validação; pedir revisão ao colega.
8. Integrar após revisão e atualizar o checklist quando a funcionalidade estiver comprovada.

## Cuidados

- Não criar commits vazios para simular participação nem atribuir trabalho a quem não o realizou.
- Preservar os requisitos da primeira entrega; registrar e alinhar alterações relevantes.
- Não incluir senhas, arquivos .env, credenciais ou dados pessoais de usuários de teste.
- Usar dados fictícios nas demonstrações.
- Não marcar funcionalidades e testes como concluídos apenas por estarem planejados.

O cronograma e os responsáveis originais estão no [README](README.md).
